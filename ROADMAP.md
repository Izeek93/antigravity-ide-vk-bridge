# 🗺️ Стратегическая дорожная карта: Antigravity IDE VK Bridge & MCP

Официальный план развития проекта двусторонней связи между средой разработки **Google Antigravity IDE** и экосистемой **ВКонтакте (VK)**.

---

## 🎯 Миссия проекта
Превратить локального агентного ассистента в полнофункционального автономного медиа-менеджера и инженера, доступного 24/7 с любого смартфона через личные сообщения и беседы ВКонтакте, с нулевыми задержками и промышленным уровнем отказоустойчивости.

---

## 📍 Релизы и текущий прогресс

### 🟢 Фаза 1: Фундамент и базовая связь (Релиз v1.0.0 — Август 2026) — `ВЫПОЛНЕНО`
- [x] Автономный демон LongPoll для работы без белого IP и проброса портов.
- [x] Обработка текстовых и голосовых сообщений (STT через локальный Whisper).
- [x] Базовый статус-трекер (индикация активности и набора текста).
- [x] Авторизация и белый список пользователей по ID (`VK_ALLOWED_USER_IDS`).

---

### 🟢 Фаза 2: Отказоустойчивость и нейроголос (Релиз v1.1.0 – v1.1.1 — Сентябрь 2026) — `ВЫПОЛНЕНО`
- [x] **Decoupled Architecture**: разделение приёма сообщений (`inbox.json`) и отправки (`send_vk.py`) с OS-level файловыми блокировками (`portalocker`).
- [x] **OmniVoice TTS Integration**: локальный синтез естественной русской речи (модель Eva) на аппаратном бэкенде Vulkan GGML.
- [x] **Интерактивные терминальные карточки статуса**: динамический прогресс-бар, пошаговые тайминги (STT ➔ IDE ➔ TTS ➔ VK) и честный подсчёт контекстных токенов.
- [x] **Экстренная система SOS**: аппаратное прерывание зависших инференс-процессов по нажатию кнопки в чате или текстовой команде (`сос`, `стоп`, `/sos`).
- [x] **Single-Instance Enforcement**: защита от конфликтов нескольких запущенных процессов LongPoll.

---

### 🟢 Фаза 3: Отказоустойчивый супервизор и MCP Action Layer (Релиз v1.2.0 — Сентябрь 2026) — `ВЫПОЛНЕНО`
- [x] **Self-Healing Watchdog (`bridge_supervisor.py`)**:
  - Автоматический контроль жизненного цикла демона без прав администратора Windows (Zero UAC).
  - Мгновенный перезапуск за `<0.5с` при сетевых разрывах.
  - Защита от шторма перезапусков (экспоненциальный backoff до 5с).
  - Экспорт метрик надёжности в `supervisor_status.json`.
- [x] **Stdio FastMCP Server (`vk_mcp_server.py`)**:
  - Нативная интеграция в Antigravity IDE через `mcp_config.json`.
  - 5 встроенных инструментов: отправка сообщений, нейро-голосовые заметки, публикация на стену группы, загрузка фото и диагностика.
  - Строгая изоляция потоков (stdout под JSON-RPC, логи в stderr).
- [x] **Автоматизированное тестирование**: 100% покрытие базовых сценариев (`test_vk_mcp.py`).

---

### 🟡 Фаза 4: Мульти-топики, модерация контента и опросы (Релиз v1.3.0 — Q3 2026) — `В РАЗРАБОТКЕ`
- [ ] **Тематические чаты сообщества (VK Topics)**:
  - Поддержка нескольких бесед сообщества с раздельными контекстами (чат «Идеи», чат «Медийка», чат «Разработка»).
  - Роутинг сообщений по `peer_id`.
- [ ] **Интерактивный конвейер предмодерации контента**:
  - Бот генерирует пост (текст + сгенерированная иллюстрация из ComfyUI).
  - В специальный закрытый чат кураторов отправляется карточка с кнопками: `[✅ Опубликовать]`, `[🔄 Перегенерировать]`, `[❌ Отклонить]`.
  - Публикация на стену только после клика куратора.
- [ ] **Поддержка User-токена администратора**:
  - Чтение архива стены (`wall.get`), аналитика охватов, комментариев и вовлеченности подписчиков.

---

### 🔵 Фаза 5: Двухуровневый шлюз и облачный Webhook (Релиз v2.0.0 — Q4 2026) — `В ПЛАНАХ`
- [ ] **Edge Webhook Gateway**:
  - Серверлесс-воркер (Cloudflare Worker) для мгновенного приёма вебхуков от VK/Telegram.
  - Постоянный защищённый WebSocket/Tunnel к домашнему ПК.
  - Буферизация сообщений в облаке: если ПК спит, сообщения накапливаются и обрабатываются сразу после пробуждения.
- [ ] **Микро-роутер быстрых ответов (Router Agent)**:
  - Мгновенный ответ за `<0.3с` на сервисные команды и статус без пробуждения тяжёлого ядра IDE.
- [ ] **Мульти-мессенджерная синхронизация**:
  - Единое ядро памяти и задач для VK и Telegram с возможностью бесшовного переключения между ними.

## 🤝 Вклад в проект (Contributing)
Мы приветствуем Pull Request'ы и предложения! Пожалуйста, следуйте правилам:
1. Код должен соответствовать PEP8 и иметь 100% UTF-8 совместимость на Windows/Linux.
2. Новые функции ядра должны сопровождаться автотестами в папке `tests/`.
3. Все MCP-инструменты должны логировать строго в `stderr`.
